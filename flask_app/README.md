# News Recommendation System - Flask Backend

## How the folders fit together

```
DATA-SCI\                 <- notebooks, raw data, and notebook OUTPUT live here
   data.csv  Fake.csv  True.csv
   news_recom.ipynb      <- generates 3 of the 4 required files
   Fake_News_Detection.ipynb  <- generates the 4th
   tfidf_vectorizer.pkl, tfidf_matrix.npz, similarity_table.csv, cleaned_data_with_fake_news.csv

   flask_app\             <- the web app itself
      app.py  models.py  news_api.py  premium.py  templates\
      + a COPY of the same 4 data files (the app only looks in THIS folder)
```

The app deliberately reads its data from its own folder, so it runs no matter
where the project sits on disk. The trade-off is that **if you re-run a
notebook you must copy the new files across** (step 5 below), otherwise the app
keeps using the stale ones.

## Setup

Requires **Python 3.10-3.13** (3.11 recommended).

**1. Open a terminal in the `DATA-SCI` folder** (the one holding `news_recom.ipynb`).

**2. Create a virtual environment**

   Windows:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   ```
   macOS / Linux:
   ```
   python3 -m venv .venv
   source .venv/bin/activate
   ```

**3. Install dependencies**
   ```
   pip install -r flask_app\requirements.txt
   ```

**4. Create your own settings file**

   ```
   copy flask_app\.env.example flask_app\.env
   ```
   macOS / Linux: `cp flask_app/.env.example flask_app/.env`

   Then open `flask_app\.env` and fill in whatever you have. **All four values
   are optional** -- with an empty file the site still starts, you just lose
   some features:
   - `SECRET_KEY` blank -> you get logged out each time you restart
   - `NEWS_API_KEY` blank -> live news falls back to Google News RSS (works, no key needed)
   - `GEMINI_API_KEY` blank -> the fake-news checker uses a weaker fallback

   Do **not** share your `.env` with anyone -- it holds your personal keys.

**5. Put the four data files in `flask_app\`**

   They are already in the project root, so on Windows just run:
   ```
   copy cleaned_data_with_fake_news.csv similarity_table.csv tfidf_vectorizer.pkl tfidf_matrix.npz flask_app\
   ```
   macOS / Linux:
   ```
   cp cleaned_data_with_fake_news.csv similarity_table.csv tfidf_vectorizer.pkl tfidf_matrix.npz flask_app/
   ```

   If those files are **not** in the root folder, generate them by running the
   two notebooks from the root folder, in this order (about 15 minutes total):

   1. `news_recom.ipynb` -> `tfidf_vectorizer.pkl`, `tfidf_matrix.npz`, `similarity_table.csv`
   2. `Fake_News_Detection.ipynb` -> `cleaned_data_with_fake_news.csv`

   `news_recom.ipynb` also needs `data.csv`, `Fake.csv` and `True.csv` in the
   same folder. Those three raw files are ~520 MB combined and are not
   regenerated by anything.

**6. Run it**

   ```
   python flask_app\app.py
   ```
   Then open **http://127.0.0.1:5000**

   The database (`instance\db.sqlite3`) is created automatically, along with
   your first account. You can also run it from inside the folder with
   `cd flask_app` then `python app.py` -- both work.

**To debug**, add `FLASK_DEBUG=1` to `flask_app\.env`. Only do this on a
network you trust: the debugger lets anyone who opens the site run Python code
in their browser.

**Port already in use?** Set `PORT` in `.env` (e.g. `PORT=5055`) or stop whatever
is holding port 5000.

## If something goes wrong

| Message | Cause and fix |
|---|---|
| `ERROR: the app could not find these required data files` | The four files aren't in `flask_app\`. See step 5. |
| `No module named 'flask'` | You skipped the virtual environment, or forgot to activate it (step 2). |
| `No module named 'psycopg2'` | Only happens if you set `DATABASE_URL`. Run `pip install psycopg2-binary`. |
| `Port 5000 is already in use` | Set a different `PORT` in `.env`, or close the other program. |
| `UnpicklingError` / `InconsistentVersionWarning` | `scikit-learn` is a different version from the one used to build the files. Install exactly `scikit-learn==1.9.0`. |
| Live news is empty | NewsAPI's free tier allows 100 requests/day. Wait for the reset, or leave `NEWS_API_KEY` blank to use the RSS fallback. |

## What's on the site

- Home feed: a pinned "Top News" section, plus a feed that shuffles every refresh
- Search bar (searches title + category)
- Category menu (Sports, Business, Cinema, Technology, Health, Education,
  Politics, Science, Travel, Food)
- Article pages: recommendations, like/dislike, and a language selector
  that translates the title/description on the fly (needs internet --
  see note below). "Read full article" fetches the publisher's full text
  and shows it on our own page, with a back link to the article
- "Enable Notifications" button (top left): a real browser desktop
  notification showing today's top headline, using the browser's own
  Notification API -- no server-push infrastructure required
- Premium landing page (/premium): pricing + a demo "Subscribe" button
  (no real payment gateway -- just flips a flag and logs to RevenueLog)
- Fake News Checker (/fake-checker): premium-only. Paste any headline or
  article text; Gemini AI checks the claim against current web coverage
  and returns a Real/Fake verdict with a short explanation, plus related
  articles pulled from the actual dataset
- Admin dashboard (/admin/dashboard): revenue + engagement numbers

## A note on article links

Live/search articles are kept in two places: an in-memory cache (fast, but
cleared on restart and trimmed once it passes 1,000 entries) **and** the
`live_article` table in `db.sqlite3`. Opening `/live-article/<id>` checks the
memory cache first and falls back to the table, recomputing the article's
TF-IDF vector on the way in. So a link to an article you saw earlier keeps
working across restarts instead of bouncing to the home page. The table is
trimmed to the 20,000 newest articles.

Every dataset article is already permanent (it comes from the CSV), so the
"Related Articles From Our Archive" block on a live article page always
resolves.

## About the language translator

Translation uses the `deep-translator` library, which calls Google
Translate's public endpoint over the internet. This needs a working
internet connection when you run the app -- it was NOT testable inside
the sandbox this was built in (only a few domains are reachable there),
but it's a standard library and will work normally on your own machine.
If the request fails for any reason (no internet, translation service
down), the page falls back to showing the original English text with a
small notice, instead of breaking.

## Creating an admin account

Sign up normally through the site, then open a Python shell in this folder and run:

    from app import app, db
    from models import User
    with app.app_context():
        user = User.query.filter_by(email="your@email.com").first()
        user.is_admin = True
        db.session.commit()

Then visit /admin/dashboard while logged in as that user.

## A note on the category menu

The category links (Sports, Business, Cinema, etc.) point to real
values in your dataset's `category` column -- "Business" links to the
underlying category "Finance", and "Cinema" links to "Movies", since
those are the actual labels present in the data. You can review/rename
these in the NAV_CATEGORIES list near the top of app.py.
